# 付款後自動成立訂單、寄客人版工作單、後台確認訂單 設計

日期：2026-11-16　狀態：規劃完成，使用者已確認，尚未實作

## 1. 目標流程

1. 客人送出訂單（不寄信），前往模擬 LINE Pay。
2. 按「付款成功」→ 系統自動：標為已付款、建立訂單與工作單（待確認）、寄「客人版工作單」到客人信箱。
3. 後台檢視內容，按「確認訂單」並填交期 → 工作單改為「已排程」，寄交期通知給客人。

## 2. 付款寫入資料庫

- 送出訂單時，`submit-manual-inquiry` 產生一次性付款憑證（隨機 32 bytes，hex），只回傳給客人瀏覽器；資料庫只存 SHA-256 雜湊。
- 新 Edge Function `mock-payment`：輸入訂單編號、憑證、結果（paid / failed / cancelled）。憑證相符才更新；已付款的訂單不可再改。加上送出頻率限制。
- Migration：
  - `manual_inquiries` 新增 `payment_status`（unpaid / paid / failed / cancelled）、`payment_token_hash`、`paid_at`。
  - `orders.quote_id` 改為可為空（付款成立的訂單沒有正式報價），新增 `payment_method`（`linepay-demo`）、`paid_at`。
  - 新 RPC `create_paid_order`：只限 service role 呼叫；以送出時後端重新計算的試算金額建立訂單與工作單快照（格式比照 `accept_quote`，`quote` 欄位改放試算明細），工作單狀態 `pending_confirmation`。重複呼叫回傳同一筆。

## 3. Email

- 送出訂單時不再寄「系統試算報價單」。
- 付款成功：寄「客人版工作單」——與工作單同一份資料，去掉負責人、製作進度、內部製作備註。內容：訂單編號、產品規格、封面、加工、數量、逐項金額、運費、總額、配送方式與地址、付款狀態（LINE Pay 示範・已付款）、「專人確認後會通知交期」。
- 後台確認訂單後：寄交期通知（訂單已確認，預計交期 X 月 X 日）。
- 寄信失敗不影響付款與訂單成立，後台顯示「信件未寄出」並可重寄。

## 4. 後台

- 首頁新增「已付款・待確認」清單；「未付款／付款失敗」另一清單，只能檢視，不產生工作單。
- 訂單詳情：客人資料、規格、附件、金額明細、付款狀態與時間。
- 主要按鈕「確認訂單」：填交期，需 manager 以上（沿用工作單確認權限）。確認後照原本方式更新製作進度。
- 「寄正式報價」功能先隱藏，程式與資料表保留。

## 5. 前台

- 模擬 LINE Pay 頁改為呼叫 `mock-payment`，以後端結果顯示狀態；失敗時顯示錯誤並可重試。
- 下單完成頁文字改為「付款後會寄出訂單明細」。

## 6. 實作順序

1. Migration 與 RPC。
2. `mock-payment` 函式、客人版工作單信、交期通知信；`submit-manual-inquiry` 停寄試算信並回傳付款憑證。
3. 前台模擬付款頁串接後端。
4. 後台清單、訂單詳情、確認訂單。
5. 測試，部署 migration 與 Edge Functions。

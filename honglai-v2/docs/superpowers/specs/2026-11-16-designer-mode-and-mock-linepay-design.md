# 查價／下單雙模式（一般客戶／設計師）與模擬 LINE Pay 結帳 設計

日期：2026-11-16　狀態：規劃完成，價格與估計值已經使用者確認，尚未實作

## 1. 目標

- 查價頁 `/quote` 與下單頁 `/order` 上方加「一般客戶｜簡單選」與「設計師｜專業規格」切換。
- 所有產品都開放設計師模式；一般客戶模式維持簡單、一目了然。
- 兩模式共用同一份產品清單與同一個計價引擎（`supabase/functions/_shared/pricing.ts`），只差顯示的欄位。
- 下單送出後直接進入模擬 LINE Pay 結帳（示範網站，不等專人確認）。

## 2. 模式切換

- 模式存在草稿 `Draft.mode: "simple" | "designer"`（`src/lib/order-draft.ts`），查價帶到下單時保留。
- 切換模式時保留共用值（數量、尺寸、配送）；設計師專屬欄位在一般模式下不送出、不計價。
- 規格摘要、Email、工作單、後台都標示所用模式。

## 5. 印刷費

單位：元／張（雙面＝一張紙正反兩面合計），已含紙張費。

| | A4 單面 | A4 雙面 | A3 單面 | A3 雙面 |
|---|---|---|---|---|
| 黑白 | 0.6 | 1 | 0.8 | 1.2 |
| 彩色 | 3 | 6 | 5 | 8 |

- 每行印刷費 = 單價 × 張數 × 本數，每一行小計算完再四捨五入。
- 混合印刷：彩色、黑白各一行。
- 尺寸對照：B5、A5 → A4 價；B4、25×25 → A3 價；橫式（A4R 等）同直式。
- 價目以 `PRICE_VERSION` 管理，新增於計價引擎並補 `pricing.test.ts` 測試。

- 內頁印刷新增「不需要（自備已印好內頁）」選項，選了就不收印刷費。

## 5b. 所有產品都能算出價格

原則：價目表有的照價目表；沒有的補「估計價」（在試算明細的來源欄標「估計價」，方便日後改正）。不再出現「需要專人報價」。

### 目前沒有自動計價、但價目表有資料的產品

- 後端欄位驗證（`validation.ts`、`invalidPricingFields`）接受設計師欄位。

## 7. 模擬 LINE Pay 結帳

- 新頁面 `/checkout/linepay/?order=<訂單編號>`：顯示訂單編號、金額，三個按鈕「付款成功／付款失敗／取消」。
- 付款結果（未付款／已付款／付款失敗／已取消）顯示在結帳頁並存在這台裝置的瀏覽器（localStorage），不寫入資料庫：模擬付款沒有真正的金流回呼，開一個公開 API 讓任何人改付款狀態並不安全。之後接真正金流時再加資料庫欄位。
- 頁面明確標示「示範用模擬付款」，不使用 LINE 官方 Logo，避免被誤認為真實付款頁（網站會公開部署到 GitHub Pages）。
- 正式報價確認頁與正式報價 Email 的「不是線上付款」字樣保留：那是專人寄出的報價確認，本身確實不是付款。

## 8. 實作順序

1. 計價引擎：紙種資料、張數換算、印刷費、尺寸對照、共版標示，加測試。
2. 查價頁／下單頁：模式切換與設計師欄位。
3. 後端驗證、Email、工作單、後台顯示模式與設計師規格。
4. 模擬 LINE Pay 頁面與付款狀態。
